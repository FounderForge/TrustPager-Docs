TrustPager Developer Docs

TrustPager is an AI-first CRM platform. AI assistants like Claude Code use TrustPager as a tool surface to run a workspace end-to-end — opportunities (deals), contacts, companies, automations, voice agents, scheduling, documents, forms, transcripts, and more. This page is the entry briefing for AI agents working against TrustPager.

Get connected

  • REST API base URL: https://api.trustpager.com/functions/v1/api/v1
  • Auth: Authorization: Bearer tp_live_... — one key per workspace
  • Create or rotate your key: https://app.trustpager.com/settings/api
  • MCP server: each workspace has its own install URL on the same Settings → API page. Recommended for interactive AI sessions.
  • Welcome / discovery endpoint: GET https://api.trustpager.com/functions/v1/api/v1/ — returns a JSON manifest pointing at every other artefact listed below. No auth required.

Common tasks (cookbook)

Recipes are paste-ready markdown. Read these before fanning out into bulk REST calls — they tell you which surface to use and what gotchas to avoid.

  • Bulk-fetch transcripts — paginate /transcripts via REST, save to disk, analyse offline.
  • MCP vs REST — when to use which — decision rules + side-by-side. Both surfaces hit the same workspace.
  • Paginate correctly — ?limit, ?after, has_more, field selection, expansions. Same pattern on every list endpoint.

Key concepts

  • Scopes. API keys are scoped (e.g. contacts:read, opportunities:write, admin). The admin scope is a superscope. Scopes are stamped on the key at creation time.
  • Approval queue. Keys with -approval scopes return 202 on writes with an approval_id. The action is queued, not executed. Do NOT retry. Check GET /approvals/:id.
  • Pagination. { data, pagination: { has_more, next_cursor } }. Pass next_cursor back as ?after=. Default limit 25, max 100.
  • Idempotency. Send Idempotency-Key: <unique> header on writes to prevent duplicates on retry. Same key within 24 hours returns cached response.
  • Error responses. 401/403/404 bodies include a docs URL and structured auth_scheme / required_scopes fields. Headers include WWW-Authenticate: Bearer realm="trustpager" and Link: <docs>; rel="help". If you hit auth issues, the error itself tells you where to look.
  • Credit costs. Reads are free. Writes are billed; AI generation and sends are billed more. MCP rates are ~10x cheaper than REST flat-rate.

Discovery surface — machine-readable everything

  • OpenAPI 3.1 spec — declares bearerAuth with bearerFormat: tp_live_*. Every endpoint, every param, every scope.
  • llms.txt — llmstxt.org-format briefing (same content as this page, plus full resource inventory)
  • llms-full.txt — every endpoint inlined with curl + params + scopes
  • api-index.json — JSON map of resources → endpoints with metadata
  • sitemap.xml — every public URL on this site
  • /.well-known/ai-plugin.json — ChatGPT-plugin-compatible manifest. Names this OpenAPI spec, the MCP install URL, and the auth scheme.
  • /.well-known/api-catalog — RFC 9727 API catalog

Per-endpoint markdown reference

Every resource has a dedicated markdown file fetched on demand:

  • Contacts — manage individuals (people) in the CRM
  • Companies — manage business accounts
  • Opportunities — sales pipeline (legacy alias: deals)
  • Pipelines — stages and pipeline management
  • Automations — triggers, actions, runs
  • Transcripts — call and meeting transcripts
  • Email — send, reply, threads, logs
  • SMS — send and receive
  • Phone — numbers and call logs
  • Voice Agents — AI voice agents (inbound + outbound)
  • Scheduling — bookings, availability, event types
  • Forms — form templates, submissions, prefills
  • Signing — document signing envelopes
  • Files — uploads, attachments, folders
  • Automations — workflow triggers and actions
  • …and 40+ more — see the full inventory in llms.txt
